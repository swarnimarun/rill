## Implemented behavior

`rill lsp` provides diagnostics, inferred-type hover, scoped definitions,
document symbols, completion and formatting. It uses compiler syntax, source
origins, module resolution and checking through the existing compiler.
Versioned UTF-16 edits apply atomically, including unsaved imported files.
Library buffers do not require an executable `main`. Editor analysis does not
execute a native compiler, pkg-config, imported code or SDL3.

Braced `if` may omit `else` when its body has unit type:

```rill
fn main() {
    let mut result = 0;
    if not false {
        result <- 42;
    };
    result
}
```

The omitted branch is an implicit unit expression with a zero-width source
origin. The condition executes once, effects and ownership cleanup agree
across execution paths, and execution continues after the conditional.
Value-producing branches and legacy `if ... then ...` still require `else`.
A bare `-3` inside a block supplies that block's value; it is not an early
function return. The SDL3 main now uses conditional initialization, an explicit
result variable and matching renderer/window cleanup.

The generated Tree-sitter parser uses ABI 15. It includes highlights, locals
and tags, accepted legacy syntax, native declarations and `not`/`!`.
ABI 15 is required so reserved-word exclusions actually take effect.
Helix setup adapts generic numeric, member, namespace and escape captures to
Helix scopes. Neovim loads the shared parser directly. VS Code uses a separate
TextMate grammar with the same stdio server.

## Host and editor evidence

Verified on AArch64 macOS with Rust 1.99.1, SDL3 3.4.18, Tree-sitter CLI 0.27.1,
Helix 25.07.1 and task-local Neovim 0.11.5.

- `python3 editors/helix/test/setup_test.py`: 7 passed, including preservation,
  backups, query symlinks, rollback and capture adaptation.
- Real Helix PTY smoke with a copy of the installed user profile: parser and
  all query health checks passed. Actual rendered keyword, numeric, member,
  namespace and escape scopes were observed. The current SDL3 source opened,
  an unsaved invalid edit produced diagnostics, undo cleared them, and shutdown
  returned a response before both editor and server exited. Source bytes on
  disk remained unchanged.
- The reviewed Helix setup was installed with dated backups. Other language
  entries, `config.toml` and the pre-existing compiler symlink were verified
  unchanged. The Rill server entry points directly at this checkout's release
  executable. `hx --health rill` passed against the installed profile.
- `python3 editors/tree-sitter-rill/scripts/verify.py --check-generated`:
  7 exact corpus cases and 48 repository sources passed. Generated bytes were
  reproducible. Real highlight rendering, locals/tags, incremental reparsing,
  NUL handling, 20 reserved keywords, 8 contextual names, 9 rejected forms and
  error recovery passed.
- Actual Neovim smoke passed parser/highlight loading, incremental recovery,
  LSP attachment, symbols, live diagnostics, clearing and shutdown.
- VS Code client/TextMate tests: 7 passed. A VSIX was packaged and dependency
  audit reported zero vulnerabilities. A VS Code GUI extension host was not
  available, so no GUI-host success is claimed.

The installed-profile Helix smoke can be repeated without changing source:

```sh
python3 editors/helix/test/smoke.py \
  --source-config "${XDG_CONFIG_HOME:-$HOME/.config}/helix" \
  --server "$PWD/target/release/rill" \
  --output /tmp/rill-helix-proof-new
```

Use a new output directory. The smoke refuses auto-save because it intentionally
edits the real source buffer without saving. See the [Helix guide](../../editors/helix/README.md)
for staging, installation and editor commands.

## Compiler and native verification

Final default regression run: 91 test targets, 600 passed, zero failed;
doc tests passed. This includes all ten current voxel tests.

The complete default suite is built with `cargo test --locked --no-run
--message-format=json`, then every discovered test executable runs with two
test threads and three targets in parallel, followed by `cargo test --locked
--doc`. The final run uses an isolated target directory. This is the same
test inventory as the ordinary Cargo suite, with bounded target concurrency.

Feature-enabled affected checks passed 270 tests across 10 targets:

```sh
SDKROOT="$(xcrun --show-sdk-path)" \
CARGO_TARGET_DIR=/tmp/rill-final-import-target \
cargo test --locked --features c-import --lib --bin rill \
  --test conditional_if --test lsp_protocol --test lsp_analysis \
  --test module_overlays --test selected_c_import --test sdl3_direct \
  --test sdl3_capture --test sdl3_lifecycle \
  -- --test-threads=2 --nocapture
```

These include actual SDL3 direct and generated bindings, Zig, framebuffer
capture and failure/cleanup traces. The current complete direct example also
passed `check`, formatter `--check`, a release-compiler native build at `-O2`
and its full dummy-video game round, printing `0` with empty runtime stderr.
Five conditional tests cover interpreter/reference/typed/C agreement,
malformed syntax, complete source origins and owner cleanup at `-O0`/`-O2`.

`cargo fmt --all -- --check` and strict all-target Clippy passed with both
default features and `--features c-import`. The release compiler built
successfully. Final diff inspection excluded runtime logs, parser binaries,
editor caches and dependency directories; generated parser C/metadata are
intentional package sources.

Filesystem capability skips remain: two default-test subcases and one
feature-test subcase cannot create invalid-byte filenames in this sandbox.
SDL3 and Zig checks ran against installed dependencies and did not skip.

Earlier verification attempts caught two environmental/snapshot issues. A
feature-enabled SDL test used a concurrently replaced default-feature binary;
isolating its Cargo target directory fixed that test setup. A full run saw an
older seven-test voxel snapshot while another workspace task was updating it.
All ten current voxel tests passed on rerun. No voxel source changes were made
as part of the editor work.

Local verification artifacts are under `/tmp`: `rill-helix-full-default-final.log`,
`rill-helix-feature-isolated.log`, `rill-helix-tree-sitter.log`,
`rill-helix-neovim.log` and `rill-helix-final-proof/summary.json`.

## Review and remaining limits

Independent review found and regression tests fixed call-member/name
collisions, legacy-local scope leakage, completion shadowing, nested module
entry context and a contextual `export` declaration-name collision. Final
review found no remaining actionable issue in those changes, conditional
lowering/source mapping or Helix installation.

Analysis currently recomputes snapshots. Local navigation needs a successful
parse, and semantic diagnostics without source spans anchor at document start.
Keep the unique program entry open when editing nested modules; ambiguous
entry contexts report `E-LSP-CONTEXT`. Rename, references, code actions,
signature help and debugger mappings remain unimplemented and unadvertised.
See [editor support](../editor-support.md) for protocol bounds and setup.
