# Existing Copy vectors on checked typed execution

This bounded increment migrates the existing `u8x16` type and its eight builtins
onto the shared, independently verified interpreter/C path. It follows the
reviewed Copy-field-loan checkpoint. It adds no vector semantics, stable ABI,
performance guarantee or phase-completion claim.

## Representation and contract

`U8x16` is a Copy type with a closed operation enum. Independent verification
checks operation arity, every operand type and the result type. `load` requires
a fixed byte buffer and an `i32` offset; `lane` requires a vector and an `i32`
index. AND/OR/XOR/lane-wise equality take two vectors; any/all take one vector
and return a boolean. Invalid IR is rejected before evaluation or emission.

A load snapshots its buffer before evaluating the offset. It accepts a
nonnegative offset no greater than capacity minus sixteen, with capacity at
least sixteen. Lane indices are zero through fifteen. Invalid accesses trap;
small-capacity loads remain valid typed operations whose execution traps.
The binary operations preserve source argument order and snapshot the first
operand before later effects. Equality produces byte masks zero or 255, and
any/all treat every nonzero byte as true. Lane zero remains the first byte,
independent of endianness. There are no vector stores or borrowed-slice loads.

The C representation is a struct containing sixteen `uint8_t` lanes, with a
compile-time assertion that its size is exactly sixteen bytes. Ordered typed
temporaries retain argument evaluation order. Default operations use portable
scalar C11. The existing explicit `RILL_SIMD_NEON` selection uses AArch64 NEON
only for the four binary operations, retaining the unsupported-target guard.
Defining the macro even to zero still requests NEON. Loads, lane access and
reductions remain scalar. This is not runtime feature detection or automatic
vectorization, and the compact layout is not a public foreign ABI.

Vectors compose with concrete generic functions, finite enums/records, Copy
matches, value snapshots, root/field loans and computed read temporaries. Copy
vectors also coexist with restricted owners. The source ownership checker's
change is limited to accepting this Copy type and visiting the eight builtin
operands in order. Owner moves, loan authority, cleanup, fallible allocation,
abort behavior, monomorphic/acyclic owner restrictions, borrowed owner-enum
restrictions, owner-bearing record rejection and foreign restrictions remain.
Allocation and call-graph verification traverse vector operands independently.

## Fresh evidence

- Six source groups cover 50 supported/trapping programs. Forty-three compare
  the checked AST oracle, direct typed evaluation, production interpretation
  and identical typed/production C, plus uniform native C forced by an unused
  raw-C marker. Seven owner cases use explicit expected
  results because the AST oracle rejects owners. Native checks use strict C11
  with GCC at `-O0` and `-O2`.
- Coverage includes all lanes of AND/OR/XOR/equality across four deterministic
  generated input pairs and independent byte-level expected results, mask
  reductions, offsets/capacities zero through 256, negative/extreme indices,
  first-operand snapshots, later mutation/traps, nested display, compact layout,
  nominal/generic values, record fields, loan forwarding, owner payloads and
  the 32-active-call success/33rd-call trap boundary.
- Thirteen source rejections retain operand types/arity, invalid scalar use,
  read/inout authority and overlap, owner use after move, generic/recursive
  owner limits and owned-record rejection.
- Five private groups make 47 malformed-IR mutations across all three typed
  entrypoints. They check closed signatures, result types, capacities, scalar
  patterns/operations, field types, enclosing projected-loan intervals, hidden
  owner recursion and forged allocation metadata. Valid allocation probes also
  check exact normal cleanup, abort injection and recoverable allocation failure.
- The existing byte audit retains uniform-C comparison with an unused `u32`
  marker, now that vectors no longer force fallback. Generated byte inputs use
  separate construction functions to stay within the uniform backend's existing
  conservative 1 MiB per-function frame limit; that limit was not relaxed. Its reference is the
  unmodified Copy program's checked AST oracle. The marker program deliberately
  requires native execution; its interpreter rejection is checked rather than
  misrepresented as differential execution support.

Fresh affected checks passed all 250 tests across the library and 35 integration
binaries. This includes all existing vector tests, checked root/field loans,
records, generic specialization, owner cleanup/failure and recursion/stack
regressions. The final six source groups were rerun after adding owner-vector
returns and explicit uniform-C comparisons. The x86_64 unsupported-NEON-target regression passes. Fresh NEON
execution and AArch64 assembly inspection were not performed; the earlier
uniform-backend evidence is historical, not evidence for these new typed helpers.
Toolchain: Rust 1.99.1 and GCC 14.2 on x86_64 Linux.

Strict all-target Clippy passed in default and `c-import` modes, as did formatting
and diff whitespace checks.

Independent review found no production correctness issue in eight added groups.
It reports 395 native build/run comparisons through GCC 14 and Clang 19 at
`-O0`/`-O2` plus GCC UBSan, a bit-plane oracle covering all 256 byte values,
76 malformed-IR mutations, root/nested field loans, generic/nominal snapshots,
recursion, allocation/failure/cleanup traces, trap-visible store state, ABI
rejections and operand traversal for stack budgets. Eight explicit unsupported
NEON-target compilations reject both typed and truly uniform C, including the
macro defined to zero. An oversized independent uniform-C fixture also hit the
existing frame limit and was replaced with equivalent bounded initialization.
Recoverable-allocation probes also show that failure of either operand's
allocation preserves later evaluation, ordinary `Result` handling and successful
cleanup. Final snapshot review reran 27 tests/groups: thirteen private groups
(the five author groups plus eight independent groups) and fourteen integration
tests. All six production hashes and the complete candidate patch were
independently reconciled. Clang UBSan and fresh AArch64 execution were not run.

The combined-checkpoint full aggregate remains separate integration work. Owned-record initialization,
partial moves, CFG loans, effects, vector FFI and broader SIMD targets remain
outside this increment. See [SIMD limits](../blockers/simd.md),
[ownership](../blockers/ownership.md) and [C layout](../blockers/c-adt-layout.md).
