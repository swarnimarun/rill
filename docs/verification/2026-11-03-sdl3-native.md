# Native SDL3 verification and framebuffer captures

This report records the earlier Linux run. The subsequent
[macOS continuation](2026-11-03-sdl3-checkpoint.md) adds portable capture,
render-failure cleanup checks and real Zig/AArch64 evidence.

The direct and selected-import SDL3 paths now run against the actual library on
x86_64 Linux. This closes the earlier cloud SDL3 dependency skips. It does not
complete P5, P6, any other phase, or a foreign lifetime/effect/resource proof.

## Environment

- Debian 13, x86_64 Linux.
- Rust/Cargo 1.99.1.
- GCC 14.2.0 and Clang/libclang 19.1.7.
- SDL3 3.2.10, official Debian package `3.2.10+ds-1`.
- The SDL3 headers, runtime and development dependencies were extracted from
  official Debian packages into a private workspace prefix. No system or user
  laptop installation was required.
- The real SDL software renderer used the `dummy` video driver. Xvfb could not
  start because the execution environment forbids creating its local display
  sockets. These are **native headless framebuffer captures**, not screenshots
  of a physical desktop window.

For a relocated Debian installation rooted at `$SDL_PREFIX`, the relevant
configuration is:

```sh
export PKG_CONFIG_SYSROOT_DIR="$SDL_PREFIX"
export PKG_CONFIG_PATH="$SDL_PREFIX/usr/lib/x86_64-linux-gnu/pkgconfig:$SDL_PREFIX/usr/share/pkgconfig"
export LD_LIBRARY_PATH="$SDL_PREFIX/usr/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export RILL_TEST_CLANG_RESOURCE_DIR="$(clang -print-resource-dir)"
pkg-config --modversion sdl3
pkg-config --cflags --libs sdl3
```

The Clang executable and runtime must also be discoverable. A normal system
SDL3 development installation does not need the relocated-prefix variables.
The package's private pkg-config requirements must be available; merely
copying `SDL.h` and the shared library is insufficient.

## Actual library regression results

Both commands passed with **two real-library tests, no dependency skips**:

```sh
cargo test --locked --features c-import --test sdl3_direct -- --nocapture
CC=clang cargo test --locked --features c-import --test sdl3_direct -- --nocapture
```

The tests build and execute the actual direct game for three frames, through
both `build` and native `run`. The generated case imports the selected symbols
from installed SDL3 headers and executes the generated binding module. Each
native execution prints `0` and exits successfully. The importer preserves
`SDL_EVENT_QUIT` as `i32`, so generated-binding use explicitly converts it to
`u32` at the SDL event-query call.

The separate command below also passed:

```sh
cargo test --locked --features c-import --test sdl3_game -- --nocapture
```

That test is named `collector_gameplay_runs_without_sdl`. It uses a C **stub**
to test movement, bounds, collection and loop exit. Its gameplay assertions are
not evidence of physical keyboard input or actual SDL rendering.

## Uninstrumented application runs

The original direct game's complete 900-frame round, compiled with GCC `-O2`,
ran against actual SDL3 and printed `0` with no stderr:

```sh
out=$(mktemp -d)
cargo build --locked --features c-import
target/debug/rill check examples/sdl3-direct/main.rill
target/debug/rill build examples/sdl3-direct/main.rill \
  --c-arg -O2 -o "$out/direct"
SDL_VIDEODRIVER=dummy "$out/direct"
```

The original collector, with its unmodified C shim and no capture wrapper,
compiled with GCC `-O2` and entered its normal game loop without an SDL error.
A two-second `timeout` stopped this smoke run with status **124**, as expected
because no keyboard or window-close input was supplied. This was a bounded
startup/liveness check, not a normal-exit pass. The capture runs below separately
exercise its normal event-driven exit and resource destruction.

The collector was built with the README's shim/link workflow, adding `-O2` to
the shim compiler command and `--c-arg -O2` to `rill build`. Its bounded run was:

```sh
timeout 2s env SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software "$out/collector"
# Expected exit status: 124, with no SDL error output.
```

## Reproduce the real framebuffer captures

The checked-in [capture script](../../scripts/capture-sdl3.sh) builds both
original examples, links [a capture-only C wrapper](../../scripts/sdl3-capture.c),
and saves actual SDL framebuffer pixels. The wrapper calls
`SDL_RenderReadPixels` immediately before the real `SDL_RenderPresent`, saves
with `SDL_SaveBMP`, then posts an ordinary `SDL_EVENT_QUIT`. Neither the Rill
game source nor its drawing operations are changed.

The current script requires Bash, Python 3, pkg-config, SDL3 development files
and a C11 compiler on macOS or Linux. It redirects presentation calls at compile
time and uses Python for the process deadline; GNU timeout and linker `--wrap`
support are no longer required. Cargo is required
unless `RILL_BIN` points to an existing compiler executable. ImageMagick's
`magick` is optional; it adds lossless PNG copies without resizing, annotation,
or drawing. BMP files are always retained.

```sh
cargo build --locked --features c-import
export RILL_BIN="$PWD/target/debug/rill"
scripts/capture-sdl3.sh /tmp/rill-sdl3-o0
RILL_CAPTURE_OPT_LEVEL=2 scripts/capture-sdl3.sh /tmp/rill-sdl3-o2
CC=clang RILL_CAPTURE_OPT_LEVEL=2 scripts/capture-sdl3.sh /tmp/rill-sdl3-clang
for game in direct collector; do
  cmp "/tmp/rill-sdl3-o0/sdl3-$game.bmp" "/tmp/rill-sdl3-o2/sdl3-$game.bmp"
  cmp "/tmp/rill-sdl3-o0/sdl3-$game.bmp" "/tmp/rill-sdl3-clang/sdl3-$game.bmp"
done
```

Use new output directories. The script refuses any existing file, directory
or symlink at the output path. It cleans its temporary objects, executables
and optional compiler build; partial output is preserved if a failure needs
diagnosis. Each native capture has a 30-second timeout to bound regressions.
`CC` is a single executable, not a shell command. Pkg-config output
is parsed into argument arrays without shell evaluation. `RILL_CAPTURE_FRAME`
selects frame 1 through 900; the default is 40. `RILL_CAPTURE_OPT_LEVEL` accepts
only 0 or 2 and applies to the emitted C, shim and capture helper.

All three capture runs above succeeded and their BMP files matched
**byte-for-byte** for each game. Both programs printed `0` and exited normally.
A selected-import binding version of the direct game, compiled with GCC `-O2`,
also produced the identical frame-40 BMP. The capture script was additionally
checked with an output directory containing spaces, repeated-output and dangling-symlink rejection,
invalid-frame/optimization rejection, the frame-1 boundary, the fresh-compiler
fallback without `RILL_BIN`, and `bash -n`.
